## 2. The layer

Each part is advisory context (never a gate), default ON, with a kill-switch file and one telemetry line per decision (what
was injected, why, how many bytes) in `.jev/system1.jsonl`. Budget: at most about 2 KB injected per tool call and 4 KB per
prompt. A section is injected once per context window (a marker cleared at each compaction), so it is never repeated while it
is still in context.

- **L1: situation to skill, before the action.** A PreToolUse hook on Write, Edit and Bash recognizes the situation from the
  file path or the command (a brief under `tasks/briefs/`, a code file, `git commit`, a push, a `pc.sh` call, a background
  job, a stamp in text) and injects the governing skill section's key lines VERBATIM, plus "full details: `<file>` §
  `<heading>`". The situation table is CTX1's pointer table (CLAUDE.md's "Load `<skill>` before/when <situation>" lines, CTX1
  report section 6), turned into path and command patterns. No model is needed for these.
- **L2: the code map, before a code edit.** The post-commit hook (which already re-indexes on a code change) also writes a pack
  per changed code file: the file's skeleton (graft), the callers and the risk of its symbols (GitNexus impact), the tests that
  cover it (code-review-graph), and the registry rows its patterns match (`ap_screen.py`). The PreToolUse hook on Edit/Write of
  a code file reads the cached pack (milliseconds) and injects the part for the symbol being edited. A cache miss injects a
  one-line pointer and queues the build.
- **L3: skills beside the wiki, per prompt.** `wiki-context.py` gains a skills section: keyword matching over skill SECTIONS
  (a skill is split at its headings), the best one or two excerpts with their pointers.
- **L4: the shadow.** Deterministic rule checks on each tool call, first: a brief with no premise block; a commit not through
  `safe_commit.sh`; a push not through `push_clean.sh` or `push_when_green.sh`; a code edit whose pack was never shown; a
  typed ahead-of-clock stamp; AskUserQuestion. A hit adds a warning line to the next injection and a counted event; it never
  blocks. Laya takes the fuzzy checks later (D-047's drift-hawk).
- **L5: the bug locator.** `scripts/chat_find.py "<description or error text>"`: the first appearance in every transcript
  (session, time, record, the tool call around it), counts and positions only by default, for the registry and the wiki.
- **L6: Laya in the loop.** Laya ranks when several sections or rows match (L1, L3) and runs the fuzzy shadow checks (L4).
  Zero-shot Laya had no usable signal (D-074), so its labels come from the sessions: the situations L1 detects are labels
  (a brief was written: orchestration governed it). The fine-tune gets a `skill.governs` question type; GEPA (D-075(5)) tunes
  its instructions and criteria against about 30 hard labeled turns.

## 3. Fixes the audit found, outside the layer

1. The skill listing (D13): move the vendored library skills that this project does not use out of `.claude/skills/` into
   a library folder the harness does not load (kept in the repo, retrievable by L3), so the listing describes every
   project skill. An owner decision: it changes what the harness lists.
2. slopo: its source is unknown to the repo; the owner's link, then a pin and an installer on both venues.
3. Honey (D1): make it inject or correct the CLAUDE.md claim.
4. The search-intercept hook: a Grep took 3,761 ms after the codebase-memory hooks went; measure and cut its cost.
5. edit-snapshot named the wrong enclosing symbol (D8).
6. Installation: one pass so every tool the workflow names installs on a fresh container, with a one-line smoke per tool at
   session start.

## 4. Order and measurement

L1 first (the most direct fix for AF-AP-218, no model, CTX1's table ready), with L3 alongside; then L2 (the cache needs the
post-commit hook); L5 as a small independent lane; L4's rule checks after L1 and L2 exist; L6 as labels accumulate. Each part
ships with tests (a fixture transcript or a fixture tool call through the real hook), telemetry, and a measurement after a day
of use: injections per situation, bytes, and later how often the agent read the pointed file.

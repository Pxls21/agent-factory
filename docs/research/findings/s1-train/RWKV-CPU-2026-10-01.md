# RWKV-7 on the CPU, measured 2026-10-01 (D-126)

STATUS: 2026-10-01 16:5xZ: measured in the sandbox (4 cores, 16 GB, no GPU), recorded with D-126. Serving is NOT built
(task #448).

## The question

The owner, 2026-10-01 15:47:43Z (transcript; D-126): "are you 100% sure it can't run on CPU? ... I'm pretty sure RWKV
has a CPU runner. Double check that, first and foremost ... isn't it more efficient than [Laya]? ... Double check
everything though."

D-125 item 2 (12:2xZ) had said RWKV-7 "has no CPU path in either PC venv". That held for one runtime: the pinned
Hugging Face checkpoint's code runs on flash-linear-attention, whose kernels are Triton (GPU), and its CPU fallback
failed on 2026-09-24; vLLM-RWKV is CUDA only (AF-AP-207). It was never a limit of RWKV-7.

## Answer

Yes. RWKV-7 World 0.4B runs on the CPU, correctly, in two runtimes:

- BlinkDL's own `rwkv` package (`RWKV_V7_ON=1`): plain torch, one Python step per layer; correct, and slower than
  Laya's encoder at every length measured.
- llama.cpp (its compiled RWKV-7 graph, `src/models/rwkv7.cpp`, and the CPU kernel
  `ggml_compute_forward_rwkv_wkv7`, `ggml/src/ggml-cpu/ops.cpp`): its hidden states equal the official package's, and
  at 8 bits it reads faster than Laya's encoder at every length measured.

## What it means

- **A live home on the CPU exists.** llama.cpp gives RWKV-7's hidden states on the CPU at about 333 tokens a second
  on 3 sandbox threads at 8 bits (about 425 on 4 threads in the unbracketed run), flat with length; the f16 file gives
  the official package's numbers to float rounding, at about 61% of that speed. The owner's fallback (a fixed GPU slice cut from vLLM) is not needed for serving.
- **More efficient than Laya, at 8 bits.** Laya's encoder re-reads its whole window on every call, and its speed falls
  with length (attention); RWKV reads at the same speed at any length and carries a fixed state (6.19 MB, the `rwkv`
  package's measure), so a decision reads only the text that is new since the last one. In plain torch (the `rwkv`
  package) RWKV is slower than Laya: the runtime decides.
- **The first reading pass stays a GPU job.** The 2026-10-01 export decompresses to 463,272,856 bytes; at 3.01 bytes
  per RWKV token (a 2,000,000-byte sample of it: 664,087 tokens) that is about 154 million tokens: about 128 hours
  at the Q8_0 reading speed above on the sandbox CPU, and about 49 minutes on the 3090 (61,440 tokens in 1.17 s,
  the 2026-09-24 window). It runs in a GPU test window (D-088), or reads less (only the sessions and spans the S1 rows
  need); task #441's pre-registration decides.
- **Train on the features that serve.** Heads trained on one runtime's features and served on another's meet the
  difference between them: the 8-bit drift above, and the GPU reader's (bf16, flash-linear-attention), not measured
  here. Either the reading pass uses the serving runtime and file (llama.cpp Q8_0; a CUDA build of llama.cpp reads the
  same file on the 3090), or the heads' decisions are compared on both feature sets before they serve.

## NOT done (declared)

- The PC's CPU (12 cores) and the 0.1B model (`RWKV-x070-World-0.1B-v2.8`, about 382 MB) were not measured.
- No server: nothing serves these hidden states yet and no hook reads them (task #448). In this llama.cpp release the
  embedding tool returns one position per text unless `n_outputs_max_per_seq` is 0; the scratch copy for this check
  set it in `examples/embedding/embedding.cpp` (one line), and a server sets the same.
- The time of one decision through llama.cpp (a short new text read from a saved state) was not measured; the `rwkv`
  package took 0.664 s for 64 new tokens and 1.808 s for 256 from a copied state (above).
- The GPU reader's features against these CPU features: not measured (it needs the GPU).
- The `rwkv` package makes RWKV-7 a TorchScript module whatever `RWKV_JIT_ON` says (`rwkv/model.py:185`), so its
  weights dict reads back as a copy: `hidden.py` sets the identity head by assigning the whole dict again, and refuses
  to run if the output width is not the hidden size.

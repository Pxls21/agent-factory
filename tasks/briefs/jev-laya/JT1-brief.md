## Pinned decisions (do not redesign; a conflict with the tree is a STOP-and-report)

- **D-1 The client speaks the server's real contract.** `rank` sends `state = {"query": <q>, "chunks": [{"id": .., "text": ..}, ...]}`
  with one `noul` question per chunk id; the server then makes one model call per chunk (`_chunk_map`, `_answer`, server lines 118-156)
  and returns `fan_out`. Rejected: chunks as a dict, or many questions on one shared state. Measured 12:17Z: the dict form gave no
  fan-out and the same 0.5372 for all eight notes; the list form ranked the right note first (premise block).
- **D-2 `classify` sends one native `choice` question** (criteria = the labels). It stays in the tool, but nothing in this lane depends on
  it: a 10-way choice gave a flat distribution in the one measured case (top 0.197).
- **D-3 Venue order for `--venue auto`:** the local loopback endpoint (its `/health` answers within 1 s), then the PC endpoint through
  the bridge, then unavailable. The PC path reads `.pc-bridge.env` in-process (the token is never printed and never in argv), sends the
  request base64-encoded inside the command, decodes it on the PC and POSTs it to `127.0.0.1:47411` there with curl, and strips the
  bridge's `bind: warning: line editing not enabled` text, which can land on the data line (CLAUDE.md). `--url` overrides for tests.
  Rejected: PC first (the bridge round trip plus 336 ms p50 on the PC, against 543 ms p50 here).
- **D-4 Fail-open.** No answer = exit 3 and ONE stderr line `jev: unavailable: <reason>`; a usage error = exit 64. The import API
  (`from jev import health, ask, rank, classify`, with `scripts/` on the path) returns `None` on any failure; no exception escapes it.
  Standard library only (the hooks may import it).
- **D-5 Scrub, then cap (AF-AP-127).** Every text that leaves the process (the state, the query, each chunk) passes through
  `transcript_export.scrub` first, then the cap (`--max-chars`, default 4000 per text; Laya's window is 1,024 tokens). Rejected: cap
  then scrub (a cut can split a secret so the scrubber misses the rest).
- **D-6 The call log.** One JSON line per call in `.jev/calls.jsonl`: `ts` (UTC), `venue`, `cmd`, `n_questions`, `qtypes`,
  `state_sha256` (of the scrubbed, capped request state as sent), `answers` (as returned), `latency_ms`, `ok`, `reason`. Never the state
  text. Directory 0700, file 0600. `--no-log` skips it. These lines become labels later.
- **D-7 `jev_local.sh start|stop|status`.** Start runs the UNCHANGED server with `/root/venv-laya-probe/bin/python`, `--device cpu`,
  `--threads` (default 2: this box shares 4 CPUs with agent test runs), loopback, under `setsid nohup ... </dev/null &` on its own line,
  pid in `.jev/server.pid`, log in `.jev/server.log`; idempotent (a healthy server means no second start); exit 2 with one line naming the
  path when the snapshot is absent. Stop kills the pidfile's pid (never `pkill -f`). Status prints the health JSON or `down`. A server is
  running now (pid 30467, started by the coordinator, pidfile written): adopt it; leave one running when you finish.
- **D-8 `hiccup_scan.py` is deterministic.** The same input bytes give the same page bytes: the page's clock is the newest transcript
  timestamp, never the wall clock; every table is sorted. Standard library only. Inputs: `--project-dir` (default
  `/root/.claude/projects/-home-user`: its `*.jsonl` and `*/subagents/*.jsonl`) or `--transcript PATH` (repeatable); `--limit-bytes` per
  file; `--out` (default `docs/HICCUPS.md`).
- **D-9 Error families are a closed, committed map.** `scripts/hiccup_families.tsv`: a regex, a family name, and the covering rule
  (an `AF-AP-<n>` id or a short CLAUDE.md phrase), one row per family. Seed it with the families E4.3 names (exit code N, the harness's
  foreground-sleep block, auto-mode denial, edit-anchor misses, input validation, ripgrep timeout, user declined) and any other family
  you find with 5 or more events. For `Exit code N`, the cluster key adds the next non-empty output line. A cluster no family matches is
  `UNCOVERED`. Rejected: fuzzy matching against the whole registry (unauditable).
- **D-10 `--jev` (advisory column).** For each UNCOVERED cluster only: a lexical top 8 over the registry row titles and the CLAUDE.md
  quirk lines (the `bit 2026-` markers), then `jev.rank` over those 8; print the best match and its score, labelled "Jev suggests
  (advisory)". Jev unavailable: the column says `n/a (<reason>)`. The column never changes any other number on the page (KC-J1b).
- **D-11 Nothing secret reaches the page.** Every excerpt is normalized (numbers -> N, runs of 20+ `[A-Za-z0-9_-]` -> T, URLs -> U,
  `KEY=value` -> `KEY=V`, quoted strings over 40 characters -> S), then scrubbed with `transcript_export.scrub`, then cut at 160
  characters. The page stays under 40,000 bytes.
- **D-12 The page's sections, in order:** inputs (files, bytes parsed, lines, unparsable lines); per day (the last 14 days: tool calls,
  errors, error rate, compactions, median and p90 context tokens per request, refusal stops, "the user has not heard from you"
  reminders, foreground-sleep blocks, auto-mode denials); served model per day; agents (the last 7 days: id, the description from the
  main transcript's Agent call when you can join it, else the id only; served-model mix per assistant record; turns; errors; refusal
  stops; first and last timestamps); error clusters (the top 25: normalized line, family or UNCOVERED, covering rule, count, first and
  last seen, tools); context cost (the largest tool results by tool, `task_reminder` bytes and share); new this week (clusters first
  seen in the last 7 days).

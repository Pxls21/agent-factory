## Why (measured 2026-09-22 in the sandbox; the endpoint there is live on 127.0.0.1:47411)
jev-pruner (tamaratran/jev-pruner @ 47d017c, MIT) trims long tool output with per-chunk System One `noul` answers; its endpoint is a compiled-in TypeSafe constant, and the open Laya model (HF `convaiinnovations/laya` @ `1c5edc17a7acd8701df6fc341c0d179f1c62c982`, subfolder `typed-decisions`, PyPI `laya==0.3.5`) answers the SAME contract — `POST /v1/systemone {state, questions:{id:{type:'noul',instructions,criteria:{true,false}}}} → {answers:{id:{noul:<float>}}}`. In the pruner's batch form (the chunks inside one shared state) Laya returns ONE value for every chunk (0.598 for three unlike chunks — no discrimination); asked one chunk per state it discriminates (PASSED lines 0.468, `collected` 0.460, AssertionError 0.651, Traceback 0.615), so `scripts/laya_systemone_server.py` fans a chunk-keyed batch out per chunk. Sandbox reference for the batch below: `{c1: 0.4177, c2: 0.6723, c3: 0.4843}`, `fan_out 3`, bitwise identical on two runs, 961 / 945 ms at 4 CPU threads (torch 2.14.0+cpu, laya 0.3.5, FP32).

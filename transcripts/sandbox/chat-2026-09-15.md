Yes. That is exactly the right shape, and the brief for it is written and pushed as task #62 (lane QM0-b).

**How it works**
- A change to the server (the `medium` switch, a matrix cell's flags) is not applied on the spot. It is saved as a pending change and one small watcher process on the PC waits for it.
- The watcher applies the change only when three things are true on the same check: no lane on the local model is alive (cloud lanes are ignored, they never use it), the server has had no request in flight on two checks in a row (so your own interactive turn counts as busy), and no matrix cell is running.
- Then it restarts through the guarded install, waits for the health check, and writes one log line: applied, expired, or failed. If it waits past its cap, it says why it was blocked and leaves the change pending. It never writes the unit file early, which is the guard-after-write defect QM0 is fixing.
- The dispatcher changes too. A local lane that needs a different effort waits for the "applied" line before it starts. It never runs against the wrong setting, and it never fails the way it would have today.
